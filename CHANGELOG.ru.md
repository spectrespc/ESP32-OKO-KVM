## [1.1.0] — 2026-10-15

### Добавлено
- Двойные telnet-мосты: независимые ретрансляторы TCP→UART для UART0 и UART1,
  каждый со своим портом (`telnet0_port`, `telnet1_port`) и флагом включения.
- Опциональное логирование на SD-карту: `uart0_sd_log` / `uart1_sd_log`
  дописывают сырой трафик UART в `/sdcard/uar0.log` / `/sdcard/uar1.log`, а
  флаги по датчикам `sht21_sd_log` / `ina219_sd_log` / `ina226_sd_log` /
  `env_sd_log` периодически дописывают строки в `/sdcard/sht21.csv` /
  `ina219.csv` / `ina226.csv` / `env.csv`.
- Ротация лог-файлов: размер файлов ограничен 1 МБ с сохранением до 10
  ротированных копий (`sd_write_rotate()`).
- Публикация данных датчиков в MQTT (`mqtt_enable`, `mqtt_broker_url`,
  `mqtt_topic_prefix`): один JSON-топик на датчик (`/sht21`, `/ina219`,
  `/ina226`, `/env`), QoS 0.
- Поддержка exFAT в FatFs (включается патчем `fatfs/src/ffconf.h` из
  `main/CMakeLists.txt`, так как IDF v6.0.2 не предоставляет опции Kconfig).

### Изменено
- Одиночные ключи конфигурации `telnet_enable` / `telnet_port` / `telnet_uart`
  заменены на поля по UART `telnet0_*` / `telnet1_*`; устаревшие ключи NVS
  мигрируются один раз при загрузке.
- Единый флаг `sensor_sd_log` заменён на отдельные флаги CSV-логирования по
  датчикам.
- esp-mqtt подтягивается из ESP Component Registry (`espressif/mqtt`), так как
  в IDF v6 он вынесен из ядра.

### Исправлено
- CRITICAL: значения по умолчанию пинов SDSPI MISO/SCLK (GPIO12/13)
  отклонялись валидатором зарезервированных под USB пинов, блокируя сохранение
  любой конфигурации из веб-интерфейса. Значения по умолчанию изменены на
  GPIO18/19.
- HIGH: окно use-after-free для дескриптора MQTT-клиента (`s_mqtt`) при неудаче
  `esp_mqtt_client_start`; дескриптор теперь атомарный (C11) с
  release/acquire-упорядочиванием и публикуется только после успешного запуска.
- MEDIUM: гонка двойного закрытия telnet-моста в таймаутной ветке
  `stop_bridge`; файловые дескрипторы сокетов теперь атомарно
  инвалидируются перед `close()`.
- MEDIUM: частичный `send()` в telnet-мосте молча отбрасывал оставшиеся данные
  UART и не разрывал зависшее соединение.
- MEDIUM: заголовок CSV не перезаписывался после первой неудачи
  `sd_write_rotate`; флаг заголовка по файлу теперь устанавливается только
  после успешной записи.
- MEDIUM: ротация логов игнорировала ошибки переименования, допуская
  неограниченный рост файлов и молчаливую потерю истории; теперь ротация
  проверяет каждое переименование и возвращает ошибку вместо дописывания сверх
  лимита.
- MEDIUM: миграция NVS-ключей telnet стирала устаревшие ключи до подтверждения
  сохранности новых; теперь используется двухфазная фиксация с проверкой ошибок,
  а ключ-маркер пишется последним.
- LOW: удалено мёртвое поле `ctx->port`, `ctx->task` помечено `volatile`,
  `load_config` освобождает свои строки перед перезаписью, JSON-помощники
  конфигурации отклоняют нецелые значения, в `get_json_pin` добавлена проверка
  диапазона, а `GET /sensor` возвращает симулированные данные при отключённой
  подсистеме датчиков.

## [1.0.0] — 2026-10-14

### Добавлено
- Консоль USB Serial/JTAG и мосты UART0/UART1
- Поддержка SD-карты с файловой системой FAT (интерфейс SPI)
- HTTP REST API сервер на порту 80
- Режимы WiFi SoftAP + STA со сканированием сетей
- Драйверы I2C-датчиков: SHT21 (температура/влажность), INA219/INA226 (напряжение/ток/мощность)
- Веб-интерфейс Single Page Application (SPIFFS, 6 вкладок)
- Управление конфигурацией с постоянным хранилищем NVS
- Управление GPIO-пинами с переназначением и валидацией на лету
- Telnet TCP-мост в UART1
- Фреймворк self-test с проверкой HTTP-эндпоинтов
- Буфер системного лога с REST-эндпоинтом `GET /logs`
- `build_and_flash.sh` — единый скрипт build/flash/monitor/test
