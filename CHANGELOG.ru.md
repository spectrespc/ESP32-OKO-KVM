# История изменений

Все значимые изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

## [1.4.1] — 2026-10-31

### Исправлено
- Wi-Fi STA больше не прекращает попытки после 5 неудач: переподключение
  выполняется бесконечно с экспоненциальной задержкой 1–60 с.
- Устранено «зависание» в состоянии `connecting` при неудачном DHCP: добавлен
  таймаут 25 с и принудительное переподключение.
- `ASSOC_FAIL`, `HANDSHAKE_TIMEOUT` и `4WAY_HANDSHAKE_TIMEOUT` больше не
  считаются фатальными.
- Состояние STA, учётные данные и счётчики защищены мьютексом: HTTP-запросы и
  события драйвера больше не гоняются за одни и те же поля.
- Потерянное событие сканирования после рестарта радио больше не оставляет
  `/wifi/scan/results` навсегда в состоянии `{"status":"scanning"}`.

### Изменено
- Отключён Wi-Fi modem sleep (`WIFI_PS_NONE`): в присланном логе станция спала
  94,5 % времени и через ~34 часа получила `BEACON_TIMEOUT` (reason 200) при
  RSSI −34 dBm.
- Через 10 минут непрерывных неудач выполняется мягкий рестарт радио
  (`esp_wifi_stop` → 200 мс → `esp_wifi_start`), не чаще одного раза в
  10 минут. SoftAP недоступна 1–2 с; автоматической перезагрузки нет.
- `POST /wifi/disconnect` по-прежнему отключает автопереподключение до
  следующего `POST /wifi/connect`.

### Добавлено
- Диагностические поля в `GET /wifi/status`: `attempts`, `fail_streak`,
  `last_disconnect_reason`, `last_disconnect_reason_name`,
  `last_disconnect_age_s`, `next_retry_in_ms`, `radio_restarts`, `power_save`.
- Задача-супервизор `wifi_sup` (стек 4096, приоритет 4) и строки новых полей
  во вкладке WiFi веб-интерфейса.

## [1.4.0] — 2026-10-21

### Добавлено
- OTA-обновления по HTTP (`factory` + `ota_0`): манифест `version.json`,
  semver-сравнение, потоковая запись через `esp_ota_*`, проверка SHA-256 (PSA
  Crypto) и перезагрузка в новый слот. Периодическая проверка только сообщает
  о версии; установка — вручную (`POST /ota/update`).
- Откат bootloader'ом: образ подтверждается после успешного self-test; иначе
  следующая перезагрузка возвращает предыдущую прошивку.
- Эндпоинты `GET /ota/status`, `POST /ota/check`, `POST /ota/update`.
- Файловый менеджер SD: `GET /sd/list` и `GET /sd/download` (потоковая отдача,
  защита от path traversal).
- Экспорт настроек: `GET /config/export` (JSON-файл без секретов).
- `tools/ota_server.py` — сервер манифеста и образа.
- Вкладки **Files** и **Update** в веб-интерфейсе, поля OTA в Configuration,
  кнопка **Export settings**.
- Явная версия `1.4.0` в корневом `CMakeLists.txt`.

### Изменено
- Новая раскладка разделов: `factory` 1.625 МБ + `ota_0` 1.625 МБ + SPIFFS
  640 КБ. `nvs`/`otadata` не смещены, настройки сохраняются.
- `CONFIG_LWIP_MAX_SOCKETS` 16 → 20, `max_uri_handlers` 24 → 32.
- CSV self-test поддерживает альтернативные статусы (`200|503`).

### Исправлено
- SHT21: корректный режим *no hold master* с паузой преобразования.

### Миграция
- Прошить обычным `./build_and_flash.sh flash` без `erase-flash`: настройки
  сохраняются, после прошивки устройство грузится с `factory`.

## [1.2.0] — 2026-10-16

### Добавлено
- Управление питанием и сбросом внешнего устройства. Два настраиваемых
  GPIO (`ext_pwr`, `ext_rst`; по умолчанию GPIO20/21) управляют линией питания и
  сброса, каждый с флагом включения (`ext_pwr_enable`, `ext_rst_enable`),
  полярностью (`ext_pwr_pol`, `ext_rst_pol`) и — для сброса — настраиваемой
  длительностью импульса (`ext_rst_pulse_ms`, 10-5000 мс). Состояние питания
  сохраняется в NVS (`ext_pwr_st`) и восстанавливается при загрузке с защитой
  от дребезга GPIO.
- Новые REST-эндпоинты `GET /ext/status`, `POST /ext/power` и `POST /ext/reset`;
  оба POST-эндпоинта используют CSRF-защиту same-origin, а сброс троттлится
  до одного импульса в 2 секунды.
- Новый веб-интерфейс: вкладка «External» (тумблер питания + сброс с
  подтверждением), карточка «External device» на Dashboard и поля
  конфигурации для флагов включения, полярности, длительности импульса и
  GPIO.

## [1.1.0] — 2026-10-15

### Добавлено
- Двойные telnet-мосты: независимые ретрансляторы TCP→UART для UART0 и UART1,
  каждый со своим портом (`telnet0_port`, `telnet1_port`) и флагом включения.
- Опциональное логирование на SD-карту: `uart0_sd_log` / `uart1_sd_log`
  дописывают сырой трафик UART в `/sdcard/uar0.log` / `/sdcard/uar1.log`, а
  флаги по датчикам `sht21_sd_log` / `ina219_sd_log` / `ina226_sd_log` /
  `env_sd_log` периодически дописывают строки в `/sdcard/sht21.csv` /
  `ina219.csv` / `ina226.csv` / `env.csv`.
- Ротация лог-файлов: размер файлов ограничен 1 МБ с сохранением до 10
  ротированных копий (`sd_write_rotate()`).
- Публикация данных датчиков в MQTT (`mqtt_enable`, `mqtt_broker_url`,
  `mqtt_topic_prefix`): один JSON-топик на датчик (`/sht21`, `/ina219`,
  `/ina226`, `/env`), QoS 0.
- Поддержка exFAT в FatFs (включается патчем `fatfs/src/ffconf.h` из
  `main/CMakeLists.txt`, так как IDF v6.0.2 не предоставляет опции Kconfig).

### Изменено
- Одиночные ключи конфигурации `telnet_enable` / `telnet_port` / `telnet_uart`
  заменены на поля по UART `telnet0_*` / `telnet1_*`; устаревшие ключи NVS
  мигрируются один раз при загрузке.
- Единый флаг `sensor_sd_log` заменён на отдельные флаги CSV-логирования по
  датчикам.
- esp-mqtt подтягивается из ESP Component Registry (`espressif/mqtt`), так как
  в IDF v6 он вынесен из ядра.

### Исправлено
- CRITICAL: значения по умолчанию пинов SDSPI MISO/SCLK (GPIO12/13)
  отклонялись валидатором зарезервированных под USB пинов, блокируя сохранение
  любой конфигурации из веб-интерфейса. Значения по умолчанию изменены на
  GPIO18/19.
- HIGH: окно use-after-free для дескриптора MQTT-клиента (`s_mqtt`) при неудаче
  `esp_mqtt_client_start`; дескриптор теперь атомарный (C11) с
  release/acquire-упорядочиванием и публикуется только после успешного запуска.
- MEDIUM: гонка двойного закрытия telnet-моста в таймаутной ветке
  `stop_bridge`; файловые дескрипторы сокетов теперь атомарно
  инвалидируются перед `close()`.
- MEDIUM: частичный `send()` в telnet-мосте молча отбрасывал оставшиеся данные
  UART и не разрывал зависшее соединение.
- MEDIUM: заголовок CSV не перезаписывался после первой неудачи
  `sd_write_rotate`; флаг заголовка по файлу теперь устанавливается только
  после успешной записи.
- MEDIUM: ротация логов игнорировала ошибки переименования, допуская
  неограниченный рост файлов и молчаливую потерю истории; теперь ротация
  проверяет каждое переименование и возвращает ошибку вместо дописывания сверх
  лимита.
- MEDIUM: миграция NVS-ключей telnet стирала устаревшие ключи до подтверждения
  сохранности новых; теперь используется двухфазная фиксация с проверкой ошибок,
  а ключ-маркер пишется последним.
- LOW: удалено мёртвое поле `ctx->port`, `ctx->task` помечено `volatile`,
  `load_config` освобождает свои строки перед перезаписью, JSON-помощники
  конфигурации отклоняют нецелые значения, в `get_json_pin` добавлена проверка
  диапазона, а `GET /sensor` возвращает симулированные данные при отключённой
  подсистеме датчиков.

## [1.0.0] — 2026-10-14

### Добавлено
- Консоль USB Serial/JTAG и мосты UART0/UART1
- Поддержка SD-карты с файловой системой FAT (интерфейс SPI)
- HTTP REST API сервер на порту 80
- Режимы WiFi SoftAP + STA со сканированием сетей
- Драйверы I2C-датчиков: SHT21 (температура/влажность), INA219/INA226 (напряжение/ток/мощность)
- Веб-интерфейс Single Page Application (SPIFFS, 6 вкладок)
- Управление конфигурацией с постоянным хранилищем NVS
- Управление GPIO-пинами с переназначением и валидацией на лету
- Telnet TCP-мост в UART1
- Фреймворк self-test с проверкой HTTP-эндпоинтов
- Буфер системного лога с REST-эндпоинтом `GET /logs`
- `build_and_flash.sh` — единый скрипт build/flash/monitor/test
